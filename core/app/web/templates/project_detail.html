این توکن مثل رمز عبور است؛ با آن می‌توان به مخزن‌های شما push و pull کرد.

با هر push به شاخهٔ main، بیلد خودکار شروع می‌شود و همهٔ سرویس‌های پروژه با ایمیج جدید مستقر می‌شوند.

چند-کانتینری: تعریف سرویس‌ها با parastoo.yml 
# parastoo.yml در ریشهٔ مخزن — هر تعداد سرویس
parastoo: 1
services:
  web:                # فقط سرویس عمومی دامنه می‌گیرد
    build: .
    port: 3000
    public: true
    env: [DATABASE_URL=postgres://db:5432/app]
  db:                 # داخلی — فقط داخل شبکهٔ خصوصی همین پروژه
    image: postgres:16-alpine
    volume: dbdata:/var/lib/postgresql/data

نام هر سرویس داخل شبکهٔ خصوصی پروژه به‌عنوان نام میزبان به بقیه می‌رسد (مثلاً db:5432). سرویس‌های داخلی از اینترنت در دسترس نیستند.

پل عامل هوش مصنوعی (Agent Bridge)

با یک توکنِ مخصوص همین پروژه، عامل هوش مصنوعی شما (مثلاً Claude Code یا Cursor) می‌تواند کد را پوش کند، بیلد و لاگ‌ها را ببیند، داخل کانتینرها تست و عیب‌یابی کند (exec) و سرویس را ری‌استارت کند — فقط روی همین پروژه. دیدن کانتینرها، مخزن‌ها و داده‌های پروژه‌های دیگر و زیرساخت سرور از دید عامل خارج است و هر فراخوانی در گزارش پل ثبت می‌شود.

# ۳) کار روزانه

python3 pst.py log           # لاگ آخرین بیلد
python3 pst.py exec -- ls /app     # اجرای دستور داخل کانتینر سرویس (تست)
python3 pst.py logs --svc web      # لاگ اجرای سرویس
