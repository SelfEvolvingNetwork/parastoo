# راهنمای کامل دامنه و نیم‌سرور اختصاصی پرستو

> این سند «مرجعِ شما» است: از صفر تا صد — اینکه پرستو چطور با دامنهٔ واقعی (`zeolitecenter.ir` و بعداً هر دامنهٔ بهتر) کار می‌کند، چطور خودتان نیم‌سرور (Nameserver) می‌شوید تا دیگران دامنه‌هایشان را به شما وصل کنند، و اگر چیزی کار نکرد چطور خودتان پیدا و رفع کنید.
>
> همه‌چیز از v0.3.9 داخل خود پرستو است: یک سرویس DNS اختصاصی (PowerDNS) کنار هسته که از پنل ادمین مدیریت می‌شود. هیچ چیز بیرون سرور لازم ندارید.

## بخش ۰ — واژه‌نامهٔ ۹ کلمه‌ای

| واژه | یعنی چه | مثال از دنیای شما |
|---|---|---|
| **DNS** | دفترچهٔ تلفن اینترنت: «نام دامنه ← IP» | `zeolitecenter.ir` ← `193.151.142.128` |
| **رکورد A** | یک نام ← یک IP نسخهٔ ۴ | `panel.zeolitecenter.ir` ← IP سرور |
| **رکورد AAAA** | همان A ولی برای IP نسخهٔ ۶ | (سرور شما فعلاً IPv6 هم دارد) |
| **رکورد CNAME** | یک نام ← یک نام دیگر (نام مستعار) | `www.example.com` ← `example.com` |
| **رکورد MX** | ایمیلِ یک دامنه کجا می‌رود | برای میزبانی ایمیل مشتری‌ها |
| **رکورد TXT** | یادداشت متنی برای دنیای بیرون | تأیید مالکیت، اسپم‌فیلتر (SPF) |
| **نیم‌سرور / NS** | «مرجع رسمی» یک دامنه؛ هر دامنه باید حداقل ۲ تا داشته باشد | `ns1.zeolitecenter.ir` و `ns2.…` |
| **گلو-رکورد** | ثبت IP یک نیم‌سرور در مرجعِ مادر (ایرنیک) تا از دوراهی «برای پیدا کردن ns1 باید ns1 را پیدا کنم» فرار کنیم | در پنل ایرنیک: ns1 ← IP سرور |
| **انتشار (Propagation)** | کش شدن تغییر DNS در سراسر اینترنت؛ معمولاً چند ساعت، حداکثر ۲۴–۴۸ ساعت | بعد از تغییر NS صبور باشید |

**یک جمله که همهٔ کار را خلاصه می‌کند:** شما با پرستو «مرجع رسمی DNS» می‌شوید؛ هر دامنه‌ای که صاحبش نیم‌سرورهایش را روی شما بگذارد، شما تصمیم می‌گیرید آن نام‌ها به کجا بروند.

## بخش ۱ — نقشهٔ کلی

پرستو از ابتدا این‌ها را داشت (v0.3.8):

- **Traefik** — در ورودی سرور: پورت ۸۰/۴۴۳ را می‌گیرد و بسته به «نام دامنه» درخواست را به کانتینر درست می‌فرستد (پنل، گیت، سایت‌های مشتری‌ها).
- **ویزارد دامنه** (`/setup/domain`) — دامنهٔ پایه را عوض می‌کند، پیکربندی ترافیک را بازنویسی می‌کند و TLS (گواهی Let's Encrypt) را روشن می‌کند.
- سایت‌های مشتری‌ها روی زیردامنه‌ها: `slug.apps.دامنه-پایه`.

در v0.3.9 یک سرویس جدید اضافه شد:

- **`dns` (PowerDNS Authoritative 4.9)** — نیم‌سرور اختصاصی خودتان:
  - پورت ۵۳ سرور (TCP+UDP) را می‌گیرد؛ کل اینترنت از همین‌جا جواب دامنه‌های شما را می‌گیرد.
  - داده‌اش در یک volume داکری (SQLite) است؛ با `docker compose up -d dns` بالا می‌آید.
  - هستهٔ پرستو فقط با REST API (شبکهٔ داخلی داکر، بدون پورت عمومی، با کلید API) با آن حرف می‌زند — هیچ شلی از پروسهٔ هسته اجرا نمی‌شود.
  - **مدیریتش از پنل:** منوی «DNS» در نوار بالای پنل (فقط برای ادمین) — ساخت زون با یک کلیک، افزودن/حذف رکورد، حذف زون.
  - **API:** `GET/POST /api/dns/...` — برای عامل هوشمند و اسکریپت‌ها (در حالت توسعه با `X-Dev-Token`، همیشه با نشست ادمین).

**واحد زون و رکورد:** هر دامنه‌ای که شما قبول می‌کنید، یک «زون» در PowerDNS می‌شود. داخل هر زون، رکوردها می‌گویند هر نام به کجا برود.

## بخش ۲ — فعال‌سازی روی سرور

چیزی برای تایپ کردن ندارید؛ آپدیت خودکار خودش همه‌چیز را می‌آورد:

1. کد از گیت‌هاب پوش شده → تایمر systemd هر ~۲ دقیقه چک می‌کند.
2. `auto-update.sh` استک را با `docker compose up -d --build` بازسازی می‌کند → سرویس `dns` هم بالا می‌آید.
3. اگر دانلود ایمیج PowerDNS از Docker Hub کند/شکست خورد (تحریم‌ها): روی سرور `sudo bash scripts/fetch-images.sh` اجرا کنید (فهرست ایمیج‌ها در `deploy/images.txt` به‌روز شده).

راستی‌آزمایی استقرار (من یا شما — دو راه):

```bash
# راه ۱: از بیرون با هارنس استاندارد
python3 tests/e2e_live.py           # چک‌های dev-dns-status / dev-dns-roundtrip باید سبز شوند

# راه ۲: روی خود سرور
docker compose -f /opt/parastoo/docker-compose.yml ps
# کانتینر parastoo-dns باید Up باشد
dig @127.0.0.1 version.bind CH TXT   # یا: docker logs parastoo-dns --tail 20
```

کلید API خودکار ساخته می‌شود (volume مشترک `dns_meta`)؛ هیچ تنظیمی لازم نیست. اگر خواستید دستی تعیین کنید: در `.env` سرور `PARASTOO_DNS_API_KEY="یک-رشتهٔ-تصادفی"` بگذارید و `docker compose up -d dns core` بزنید.

**نکتهٔ سرورهای اوبونتو (systemd-resolved):** اگر کانتینر `dns` بالا نمی‌آمد و لاگش `failed to bind host port 0.0.0.0:53/tcp: address already in use` بود، علت این است که systemd-resolved روی `127.0.0.53:53` گوش می‌دهد و بایند TCP روی `0.0.0.0:53` تداخل می‌کند. نیازی به دست‌زدن به resolved نیست — فقط در `.env` سرور بگذارید و کانتینر را بازسازی کنید:

```bash
echo 'PARASTOO_DNS_BIND_IP="<IPv4-عمومی-سرور>"' | sudo tee -a /opt/parastoo/.env
cd /opt/parastoo && sudo docker compose up -d --force-recreate dns
```

در این حالت فقط پورت ۵۳ روی IP عمومی بایند می‌شود — دقیقاً همان چیزی که کلاینت‌های بیرونی و رکوردهای ns1/ns2 ایرنیک لازم دارند.

## بخش ۳ — وصل کردن `zeolitecenter.ir` به پرستو

وضعیت فعلی دامنه (بررسی شد در ۱۴۰۵/۸/۱۴): **هیچ رکوردی ندارد** — نه NS، نه A. یعنی از صفر تنظیمش می‌کنیم و چیزی خراب نمی‌شود. کل کار ~۱۵ دقیقه کلیک + چند ساعت صبر.

### گام ۱ — ساخت زون در پنل (کار شما: ۳۰ ثانیه)

ورود به پنل → منوی **DNS** → فرم «افزودن زون»:
- نام: `zeolitecenter.ir`
- نوع: **دامنهٔ اصلی پرستو**

این خودکار همهٔ این رکوردها را می‌سازد (و بعداً می‌توانید از همین صفحه کم/زیاد کنید):

| نام | نوع | مقدار | نقش |
|---|---|---|---|
| `@` (خود دامنه) | A | `193.151.142.128` | وب‌سایت ریشه |
| `www` | A | همان IP | نسخهٔ www |
| `ns1` | A | همان IP | نیم‌سرور ۱ |
| `ns2` | A | همان IP | نیم‌سرور ۲ |
| `panel` | A | همان IP | پنل پرستو |
| `git` | A | همان IP | گیت داخلی |
| `apps` | A | همان IP | پایهٔ سایت‌ها |
| `*.apps` | A | همان IP | هر سایت جدید بلافاصله دامنه بگیرد |
| `@` | NS | `ns1.zeolitecenter.ir` / `ns2.zeolitecenter.ir` | اعلام مرجعیت |

### گام ۲ — ثبت دو نیم‌سرور در ایرنیک (گلو-رکورد)

ورود به `nic.ir` → **دامنه‌های اینترنتی** → انتخاب `zeolitecenter.ir` → بخش **سامانهٔ نام / Name Server** → گزینهٔ ثبت نیم‌سرور جدید (Register Nameserver / تعریف Host):

1. `ns1.zeolitecenter.ir` با IP `193.151.142.128`
2. `ns2.zeolitecenter.ir` با IP `193.151.142.128`

> **نکتهٔ مهم ns2:** سرور شما الان یک IP دارد و هر دو نیم‌سرور روی همان IP هستند. اکثر ثبت‌کننده‌ها (و معمولاً ایرنیک) این را می‌پذیرند؛ اگر ایرنیک «IP تکراری» را نپذیرفت، دو راه فوری دارید:
> - **راه الف (پیشنهادی):** یک IP دوم از هاستینگ بگیرید (معمولاً چند ده هزار تومان در ماه) — آن‌وقت ns2 را با IP دوم ثبت کنید و در پنل پرستو رکورد A مربوط به ns2 را ویرایش کنید.
> - **راه ب:** ns2 را موقتاً روی یک سرویس DNS ثانویهٔ رایگان (مثل BuddyNS یا Hurricane Electric) بگذارید که با AXFR از سرور شما کپی می‌کند — پارامتر `PARASTOO_DNS_ALLOW_AXFR` در `.env` برای همین آماده شده (بخش ۶).

### گام ۳ — تغییر NS خود دامنه

همان صفحهٔ ایرنیک، بخش «تعیین نیم‌سرور» برای دامنه:

- نیم‌سرور ۱: `ns1.zeolitecenter.ir`
- نیم‌سرور ۲: `ns2.zeolitecenter.ir`

ذخیره کنید. از این لحظه ایرنیک به دنیا اعلام می‌کند «مرجع رسمی این دامنه، سرورِ خودِ شماست».

### گام ۴ — صبر برای انتشار

معمولاً ۱ تا ۶ ساعت (حداکثر ۴۸). اگر زون را در گام ۱ ساخته بودید، **هم‌زمان با انتشار، دامنه زنده است** — هیچ کاری دیگر لازم نیست.

### گام ۵ — راستی‌آزمایی (خودتان، بدون اعتماد به چشم)

```bash
dig zeolitecenter.ir @8.8.8.8 NS          # باید ns1/ns2 را بدهد
dig zeolitecenter.ir @8.8.8.8 A           # باید IP سرور را بدهد
dig panel.zeolitecenter.ir @8.8.8.8 A     # باید IP سرور را بدهد
# یا بدون dig، با مرورگر: https://dnschecker.org
```

### گام ۶ — روشن‌کردن دامنه در پرستو و HTTPS

وقتی `dig` جواب داد: پنل → **دامنه‌ها** (`/setup/domain`) → دامنهٔ پایه: `zeolitecenter.ir` + ایمیل → **فعال‌سازی HTTPS** بزنید. ویزارد رکوردها را چک می‌کند، پیکربندی ترافیک را بازنویسی می‌کند و گواهی Let's Encrypt می‌گیرد. از این لحظه:

- پنل: `https://panel.zeolitecenter.ir`
- گیت: `https://git.zeolitecenter.ir`
- سایت‌ها: `https://slug.apps.zeolitecenter.ir`

> آدرس قدیمی `panel.193.151.142.128.nip.io` همچنان کار می‌کند (لیبل‌های ترافیک حفظ شده‌اند) — لینک‌های قبلی نمی‌شکنند.

## بخش ۴ — پذیرش دامنهٔ مشتری (چرخهٔ تکرارشونده)

هر بار که مشتری جدید می‌آید، فقط این دو طرف کار را دارند:

**سمت مشتری (یک بار، در پنل ثبت‌کنندهٔ خودش — مثلاً ایرنیک):**
- نیم‌سرورهای دامنه را عوض کند به `ns1.zeolitecenter.ir` و `ns2.zeolitecenter.ir`.

**سمت شما (۳۰ ثانیه در پنل):**
- منوی DNS → نام دامنهٔ مشتری → نوع: **دامنهٔ مشتری** → ساخت.
- رکوردهای `@` و `www` خودکار به IP سرور وصل می‌شوند؛ MX/TXT و هر چیز دیگری در صفحهٔ زون اضافه کنید.

**قالب پیام آماده برای مشتری (کپی/پیست در چت):**

> سلام؛ برای وصل‌کردن دامنهٔ شما به سرور ما، فقط این ۲ قدم لازم است:
> ۱) وارد پنل همان‌جایی که دامنه را خریده‌اید شوید (برای دامنهٔ ir یعنی nic.ir).
> ۲) بخش «نیم‌سرورها / Name Server» را پیدا کنید و هر دو مقدار را دقیقاً این بگذارید:
>    `ns1.zeolitecenter.ir`  و  `ns2.zeolitecenter.ir`
> (هر مقدار دیگری که آنجا بود را حذف/جایگزین کنید.)
> بعد از ذخیره، معمولاً ۱ تا ۶ ساعت طول می‌کشد تا در کل اینترنت پخش شود. بعدش خبر بدهید تا سایتتان را روی دامنهتان راه بیندازیم.
> اگر جایی گیر کردید، فقط اسکرین‌شات از صفحهٔ تنظیمات بفرستید؛ خودم دقیق می‌گویم چی را عوض کنید.

**چک‌لیست پذیرش (برای خودتان):**
- [ ] زون در پنل ساخته شد؟ (صفحهٔ DNS باید زون را فهرست کند)
- [ ] `dig دامنه-مشتری @8.8.8.8 NS` نیم‌سرورهای شما را می‌دهد؟ (بعد از انتشار)
- [ ] سایت مشتری ساخته شد و روی زیردامنه/دامنهٔ دلخواهش تنظیم شد؟

> **دامنهٔ مشتری = فقط DNS.** وصل‌کردن «دامنهٔ دلخواه مشتری» به «سایتِ ساخته‌شده در پرستو» (به‌جای زیردامنهٔ apps) مسیر رشد بعدی است؛ فعلاً می‌توانید رکورد A دامنهٔ مشتری را روی IP سرور بگذارید — همان زیرساخت از همین حالا جواب می‌دهد.

## بخش ۵ — مدیریت رکوردها از پنل

صفحهٔ زون: منوی DNS → روی نام زون کلیک کنید. فرم «افزودن / به‌روزرسانی رکورد»:

- **نام:** خالی یا `@` یعنی خود دامنه؛ `www`، `mail`، `*.apps` (وایلدکارد) و… — نسبی بنویسید، خودش به دامنه وصل می‌کند.
- **نوع و مقدار — مثال‌های واقعی:**

| می‌خواهم… | نوع | نام | مقدار |
|---|---|---|---|
| سایت روی `example.com` | A | (خالی) | `193.151.142.128` |
| سایت روی هر زیردامنهٔ سایت‌ها | A | `*.apps` | `193.151.142.128` |
| `www` همان ریشه باشد | CNAME | `www` | `example.com` |
| ایمیل به گوگل برود | MX | (خالی) | `1 smtp.google.com` |
| تأیید مالکیت برای سرویس‌ها | TXT | (خالی یا نامی که سرویس می‌گوید) | رشتهٔ خودشان |
| SPF (ضد اسپم) | TXT | (خالی) | `v=spf1 a mx -all` |
| دیسکورد/گوگل وِریفای | TXT | `_discord` یا همان نام | کد سرویس |

- **TTL:** جا بگذارید (پیش‌فرض ۱ ساعت). برای تغییرات پرتکرار موقتاً ۶۰ بگذارید تا سریع propagate شود.
- رکورد هم‌نام/هم‌نوع **جایگزین** می‌شود؛ حذف هر رکورد (به‌جز SOA سیستمی) با دکمهٔ حذف همان ردیف.
- رکوردهای NS ریشه و SOA را دست نزنید مگر اینکه دلیل دقیق بدانید.

## بخش ۶ — نیم‌سرور دوم (ns2) واقعی

چرا مهم است: قاعدهٔ جهانی «حداقل دو NS» است؛ با دو NS روی یک سرور، از نظر فنی قابل قبول‌اید ولی اگر آن یک سرور ۳۰ دقیقه قطع شود، همهٔ دامنه‌های شما و مشتری‌ها با هم خاموش می‌شوند. مسیرهای رشد (به ترتیب سادگی):

1. **IP دوم همین سرور** — ساده‌ترین؛ ns2 با IP دوم ثبت می‌شود. (مقاوم به «حذف اشتباهی IP»، نه به قطعی سرور)
2. **سرویس ثانویهٔ رایگان (BuddyNS / dns.he.net)** — ns2 واقعاً جای دیگر است:
   - در `.env` سرور: `PARASTOO_DNS_ALLOW_AXFR="127.0.0.0/8,::1,<IPهای-سرویس>"` و `docker compose up -d dns`.
   - در پنل سرویس ثانویه، سرور اصلی را `193.151.142.128` و زون‌ها را ثبت کنید؛ کپی خودکار (AXFR) شروع می‌شود.
3. **سرور دوم + PowerDNS** — وقتی بیزینس جدی شد؛ زون‌ها به‌صورت secondary از سرور اول کشیده می‌شوند (پرستو از قبل `--master=yes` است).

## بخش ۷ — تعویض دامنهٔ اصلی در آینده

گفته‌اید بعداً دامنهٔ مناسب‌تر می‌گیرید. چک‌لیست تعویض (همه‌چیز چند دقیقه است):

1. دامنهٔ جدید: زون را در پنل با نوع **دامنهٔ اصلی پرستو** بسازید (همان گام ۱ بخش ۳).
2. ایرنیک/ثبت‌کنندهٔ دامنهٔ جدید: ثبت ns1/ns2 (گلو) با IP سرور + تغییر NS دامنه.
3. بعد از انتشار: پنل → **دامنه‌ها** → دامنهٔ پایهٔ جدید + HTTPS.
4. برای دامنهٔ قدیمی: زونش را نگه دارید و رکورد ریشه/www را CNAME به دامنهٔ جدید کنید (تا لینک‌های قدیمی نشکنند) یا زون را حذف کنید.
5. نیم‌سرورهای عمومی از `ns1.دامنهٔ-جدید` خواهند بود — دامنه‌های مشتری‌ها را باید دوباره به nsهای جدید ببرید (این یعنی «به همهٔ مشتری‌ها خبر بده»؛ برای همین زودتر از رشد، دامنهٔ نهایی را انتخاب کنید!).

## بخش ۸ — عیب‌یابی

| مشکل | علت محتمل | راه‌حل |
|---|---|---|
| `dig … NS` خالی/خطا می‌دهد | NS در ایرنیک هنوز ست نشده یا هنوز منتشر نشده | گام ۲/۳ بخش ۳؛ ۲–۶ ساعت صبر؛ `whois zeolitecenter.ir` بزنید — ستون nserver باید پر باشد |
| NS درست است ولی `dig A` خالی | زون در پنل ساخته نشده | گام ۱ بخش ۳ — صفحهٔ DNS |
| `dig @8.8.8.8` جواب می‌دهد ولی سایت باز نمی‌شود | ترافیک/ویزارد هنوز روی دامنهٔ جدید نیست | پنل → دامنه‌ها → اعمال دامنه (گام ۶ بخش ۳) |
| گواهی HTTPS نمی‌آید | Let's Encrypt هنوز نمی‌تواند به `panel.دامنه` برسد | اول `dig panel.دامنه @8.8.8.8 A` درست شود، بعد دوباره فعال‌سازی |
| صفحهٔ DNS پنل: «در دسترس نیست» | کانتینر `dns` پایین است | سرور: `docker compose up -d dns`؛ لاگ: `docker logs parastoo-dns --tail 50` |
| کانتینر dns با `EADDRINUSE` پورت ۵۳ بالا نمی‌آید | systemd-resolved روی 127.0.0.53 گوش می‌دهد؛ بایند TCP 0.0.0.0 تداخل می‌کند | راه‌حل بخش ۲ بالا: `PARASTOO_DNS_BIND_IP=<IPv4-عمومی>` در `.env` + `up -d --force-recreate dns` (بدون دست‌زدن به resolved) |
| تغییر رکورد اعمال نمی‌شود | کش TTL | صبر به اندازهٔ TTL رکورد قبلی؛ یا TTL را موقتاً ۶۰ بگذارید |
| زون مشتری ساخته نمی‌شود: «از قبل وجود دارد» | ۴۰۹ از PowerDNS | صفحهٔ همان زون را باز کنید و رکوردهایش را ویرایش کنید |

ابزارهای چک سریع (بدون نصب چیزی): `dnschecker.org` (انتشار جهانی)، `whois دامنه` (NS ثبت‌شده)، `dig +short` (جواب سریع).

## بخش ۹ — سؤالات پرتکرار

**آیا این DNS برای کاربران داخل ایران هم جواب می‌دهد؟**
بله — سرور در ایران است؛ از داخل حتی سریع‌تر. برای کاربران خارج هم DNS معمولی (پورت ۵۳) از ایران بدون محدودیت فنی پاسخ می‌دهد.

**اگر سرور ری‌استارت شود؟**
همهٔ سرویس‌ها از جمله `dns` با `restart: unless-stopped` بالا می‌آیند؛ زون‌ها در volume پایدارند.

**مصرف منابع؟**
PowerDNS با SQLite برای ده‌ها زون و هزاران کوئری بر ثانیه روی همین سرور راحت است؛ RAM مصرفی در حد چند ده مگابایت.

**امنیت؟**
- API پاوردی‌ان‌اس فقط داخل شبکهٔ داکر است؛ از بیرون فقط پورت ۵۳ باز است.
- مدیریت رکورد فقط با نشست ادمین پنل (+CSRF) یا توکن توسعه در حالت dev.
- هر فراخوانی API DNS در `audit` ثبت می‌شود.
- DNSSEC هنوز روشن نیست (مسیر رشد بعدی؛ خطر فعلی ندارد).

**اگر بخواهم زونی را بیرون ببرم؟**
مشتری نیم‌سرورهایش را عوض می‌کند و شما زون را از پنل حذف می‌کنید. تمام.

## ضمیمه — مرجع سریع API

```
GET    /api/dns/status                     وضعیت سرویس + nsها + IP
GET    /api/dns/zones                      فهرست زون‌ها
POST   /api/dns/zones                      {"name":"example.com","kind":"customer|base"}
GET    /api/dns/zones/{zone}               زون + همهٔ رکوردها
POST   /api/dns/zones/{zone}/records       {"name":"www","type":"A","content":"IP","ttl":3600}
DELETE /api/dns/zones/{zone}/records?name=&type=
DELETE /api/dns/zones/{zone}               حذف کامل زون
```

- دسترسی: نشست ادمین پنل، یا در حالت توسعه هدر `X-Dev-Token`.
- انواع مجاز: `A, AAAA, CNAME, MX, TXT, NS, SRV, CAA` — `SOA` از این مسیر مدیریت نمی‌شود.
- `kind=base` یعنی دامنهٔ اصلی پرستو (رکوردهای panel/git/apps/وایلدکارد هم می‌سازد).
