# پرستو (Parastoo) v0.2.5

[![CI](https://github.com/SelfEvolvingNetwork/parastoo/actions/workflows/ci.yml/badge.svg)](https://github.com/SelfEvolvingNetwork/parastoo/actions/workflows/ci.yml)

پلتفرم خودمیزبانِ «ساخت، انتشار و فروش» وب‌اپلیکیشن‌ها — روی یک سرور اوبونتو، با یک دستور.

پرستو یک mini-PaaS است: کاربر ثبت‌نام می‌کند، پروژه می‌سازد، کدش را با توکن روی مخزن گیت داخلی push می‌کند، پرستو خودکار ایمیج می‌سازد، آن را روی زیردامنه منتشر می‌کند، منابع (CPU/RAM) را محدود و هزینه را ساعتی از کیف پول کسر می‌کند — و ایمیج‌ها را می‌توان در مارکت‌پلیس به دیگران فروخت.

## معماری در یک نگاه

| نقش | ابزار |
|---|---|
| کنترل‌پلین (پنل، API، ورکرها) | Python / FastAPI — کد خود پرستو (`core/`) |
| گیت داخلی + رجیستری ایمیج OCI | Gitea |
| بیلد و اجرای سایت‌ها | Docker (از طریق Docker SDK) |
| پروکسی، دامنه، HTTPS خودکار | Traefik |
| دیتابیس | PostgreSQL |

هیچ Kubernetes، GitLab یا نرم‌افزار سنگینی در کار نیست؛ پرستو فقط «چسب نازک» بین ابزارهای بالغ است و تمام منطق کسب‌وکار (کاربر، پروژه، مارکت‌پلیس، کیف پول) در `core/` lives می‌شود.

## نصب — یک دستور، مستقیم از گیت‌هاب

مخزن رسمی: `github.com/SelfEvolvingNetwork/parastoo`
روی یک سرور تازه اوبونتو ۲۲/۲۴ (حداقل ۲GB رم، توصیه‌شده ۴GB)، از طریق SSH همین یک خط:

```bash
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/parastoo/main/bootstrap.sh | sudo bash
```

`bootstrap.sh` بسته را از گیت‌هاب می‌گیرد (ترتیب تلاش: **ریلیز zip ← تاربال مخزن ← git clone**)، در `/opt/parastoo` می‌ریزد و `install.sh` را اجرا می‌کند — داکر، عبور از تحریم، توکن نصب و کل استک، همه خودکار.

- **نسخهٔ پایدار به‌جای main:**  `PARASTOO_REF=v0.2.5 curl -fsSL https://raw.githubusercontent.com/... | sudo bash`
- **زبان خروجی نصب:** ترمینال هنگام نصب کاملاً انگلیسی است — متن فارسی/RTL در SSH به‌هم می‌ریزد. پنل وب و مستندات همچنان فارسی‌اند.
- **اگر در ایران گیت‌هاب کند یا مسدود بود:**  `curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/SelfEvolvingNetwork/parastoo/main/bootstrap.sh | sudo bash`  — یا دستی: `git clone https://github.com/SelfEvolvingNetwork/parastoo.git && cd parastoo && sudo bash setup.sh`
- **اجرای مجدد = آپدیت امن:** همان دستور را دوباره بزنید؛ کد به‌روز می‌شود ولی `.env`، پیکربندی ترافیک، بستهٔ آفلاین، پشتیبان‌ها و داده‌ها (ولیوم‌های داکر) دست‌نخورده می‌مانند.

### نصب از فایل zip (بدون گیت‌هاب)

سه حالت، هر کدام یک دستور:

```bash
sudo bash setup.sh                                  # فایل zip کنار setup.sh باشد
sudo bash setup.sh parastoo-v0.2.5.zip              # یا مسیر/نام فایل
sudo bash setup.sh https://HOST/parastoo-v0.2.5.zip # یا دانلود مستقیم (zip یا tar.gz)
```

`setup.sh` خودش وابستگی‌ها (curl/unzip)، دانلود، استخراج و کپی در `/opt/parastoo` را انجام می‌دهد و بعد `install.sh` را اجرا می‌کند. حالت کلاسیک: `curl -fsSL https://HOST/setup.sh | bash -s -- https://HOST/parastoo-v0.2.5.zip` — و اگر خودتان پکیج را از قبل باز کرده‌اید، داخل همان پوشه: `sudo bash setup.sh` (معادل `sudo bash install.sh`).

### install.sh چه می‌کند (هیچ سوالی نمی‌پرسد)
1. داکر را نصب می‌کند (اگر نباشد)
2. دامنه موقت از IP سرور می‌سازد (`*.nip.io`)
3. همه رمزها را تصادفی می‌سازد و در `.env` ذخیره می‌کند (chmod 600)
4. یک **توکن نصب یک‌بارمصرف** تولید و در خروجی چاپ می‌کند
5. کل استک را با `docker compose` بالا می‌آورد و CLI `parastoo` را نصب می‌کند

در پایان، آدرس پنل + توکن نصب چاپ می‌شود. بقیه‌اش در مرورگر:

### ویزارد راه‌اندازی (۳ گام در پنل وب)
1. **توکن نصب** — همان توکنی که ترمینال چاپ کرده. چون ویزارد روی اینترنت باز است، این توکن تضمین می‌کند فقط کسی که به ترمینال سرور دسترسی دارد (خود ادمین) بتواند آن را کامل کند — نه اولین ربات اسکنری که پنل تازه‌نصب را پیدا می‌کند.
2. **حساب مدیر** — بعد از این گام، ویزارد برای همیشه بسته می‌شود.
3. **دامنه و HTTPS** — دامنه واقعی، ایمیل Let's Encrypt و بررسی زندهٔ رکوردهای DNS. وقتی سه رکورد (`panel.`، `git.`، `*.apps.`) به سرور اشاره کردند، دامنه اعمال می‌شود: روترهای ترافیک بازنویسی، گواهی صادر و همه سایت‌های موجود به زیردامنه‌های جدید منتقل می‌شوند — بدون قطعی و بدون ری‌استارت هسته. این صفحه همیشه از منوی «دامنه‌ها» در دسترس ادمین است.

### نصب با دامنه آماده (اختیاری، بدون سوال)

```bash
sudo PARASTOO_BASE_DOMAIN=example.com bash install.sh
```

این سه رکورد DNS (A) را به IP سرور اشاره دهید:
`panel.example.com` ، `git.example.com` ، `*.apps.example.com`
— HTTPS هم به‌صورت خودکار با Let's Encrypt فعال می‌شود. (اگر رکوردها هنوز آماده نیستند، همان دستور بالا با nip.io نصب کنید و دامنه را بعداً از پنل فعال کنید.)

### نصب در ایران (تحریم‌ها)

پرستو از نسخهٔ 0.2.3 **چهار لایهٔ ضدتحریم داخلی** دارد که install.sh بدون هیچ سوالی فعال می‌کند:

1. **نصب داکر**: اگر `get.docker.com` مسدود بود (403 در ایران)، خودش از مخازن اوبونتو نصب می‌کند — همیشه کار می‌کند.
2. **آینه‌های Docker Hub**: اگر Hub پاسخ نداد، کاندیدهای `deploy/mirrors.txt` را از داخل همان سرور تست می‌کند (حذف مرده‌ها، مرتب‌سازی بر سرعت) و فقط زنده‌ها — آروان‌کلاد، نوین‌کلاد، docker.ir و پشتیبان خارجی — را در `/etc/docker/daemon.json` ثبت و داکر را ری‌استارت می‌کند. لیست دستی: `PARASTOO_REGISTRY_MIRRORS="آدرس‌ها" sudo -E bash install.sh` — عیب‌یابی: `bash scripts/check-mirrors.sh`
3. **آفلاین کامل (مطمئن‌ترین)**: روی یک ماشین بدون تحریم `bash scripts/fetch-images.sh` اجرا کنید → پوشهٔ `offline-images/` را کنار پکیج روی سرور بگذارید → دوباره install.sh — ایمیج‌ها از بستهٔ محلی بارگذاری می‌شوند، هیچ pull از اینترنت نمی‌زند.
4. **بیلدها (pip/npm)**: اگر PyPI یا npm روی سرور در دسترس نبود (بعضی ISPها DNS-بلاک می‌کنند)، اولین آینهٔ زنده — به ترتیب: لیارا، پارس‌پک (آبرها)، رانفلر، کارگادان، آروان‌کلاد و پشتیبان بین‌المللی برای pip؛ npmjs.ir / npmmirror برای npm — از داخل سرور تست و خودکار در `.env` و build-arg هسته ثبت می‌شود؛ بیلد هسته و بیلدهای کاربران از آینه می‌گذرد.

بازنویسی دستی آینه‌های بیلد: `PARASTOO_PIP_INDEX_URL` و `PARASTOO_NPM_REGISTRY` در `.env` (بعد `parastoo update`). جزئیات کامل: [docs/SANCTIONS.md](docs/SANCTIONS.md)

## سیکل کاربر (خلاصهٔ استفاده)

1. **ثبت‌نام** در پنل ← حساب گیت + توکن دسترسی خودکار ساخته می‌شود
2. **پروژه جدید**: نام + فناوری (static / node / python / docker)
3. **push کد** مثل گیت‌هاب:
   ```bash
   git remote add origin http://<user>:<token>@git.example.com/<user>/<project>.git
   git push -u origin main
   ```
4. با هر push ← بیلد خودکار ← ایمیج جدید در رجیستری ← **به‌روزرسانی خودکار همه سایت‌های وابسته**
5. **انتشار سایت**: زیردامنه + پلن منابع (هزینه ساعتی از کیف پول)
6. **مارکت‌پلیس**: پروژه را عمومی کنید (رایگان یا قیمتی)؛ دیگران با یک فرم آن را روی حساب خود فعال می‌کنند؛ فروشنده بعد از کمیسیون، درآمد را در کیف پول می‌بیند.

> نکته: اپ‌های Node/Python باید روی پورت 3000 گوش دهند (`PORT=3000` به کانتینر تزریق می‌شود). اگر در ریشه مخزن `Dockerfile` بگذارید، پرستو از آن استفاده می‌کند.

## دستورهای مدیریتی

```bash
parastoo status     # وضعیت سرویس‌ها
parastoo logs core  # لاگ هسته (یا gitea/traefik/postgres)
parastoo restart    # ری‌استارت استک
parastoo update     # بازسازی هسته بعد از تغییر کد
parastoo backup     # پشتیبان دیتابیس + مخزن‌ها در backups/
sudo bash uninstall.sh   # حذف کامل
```

(برای سرورهای تحریمی: اگر بستهٔ آفلاین را با fetch-images.sh بارگذاری کرده‌اید، این دستورها به هیچ pull اینترنتی نیاز ندارند.)

## توسعه و تست

```bash
pip install -r core/requirements.txt pyyaml
python tests/smoke_test.py        # جریان‌های اصلی پنل (TestClient، بدون داکر)
python tests/smoke_wizard.py      # ویزارد نصب/دامنه/ترافیک
PARASTOO_SMOKE_OFFLINE=1 python tests/smoke_sanctions.py   # ضدتحریم (بدون شبکه؛ بدون این متغیر، آینه‌ها زنده تست می‌شوند)
```

همین سه تست در CI (GitHub Actions، فایل `.github/workflows/ci.yml`) روی هر push و PR اجرا می‌شوند — از جمله نصبِ `core/requirements.txt` با نسخه‌های پین‌شده تا هر جابه‌جایی وابستگی‌ها قبل از انتشار شکار شود. تاریخ تغییرها: [CHANGELOG.md](CHANGELOG.md). لایسنس: [MIT](LICENSE).

## شارژ کیف پول (MVP)

در این نسخه، شارژ کیف پول از **پنل مدیریت → کاربران** به‌صورت دستی انجام می‌شود (درگاه پرداخت در نسخه بعد). اگر موجودی کاربر به سقف بدهی برسد، سایت‌هایش خودکار متوقف می‌شوند و بعد از شارژ می‌تواند دوباره روشنشان کند.

## سربار منابع و قیمت‌گذاری

پلن‌ها در `core/app/config.py` (`TIERS`) تعریف شده‌اند: نانو (0.25CPU/256MB)، کوچک (0.5/512)، متوسط (1/1024) — با قیمت ساعتی پیش‌فرض که از `.env` هم قابل تغییر است (`PARASTOO_COMMISSION`، `PARASTOO_DEBT_LIMIT`). هر سایت با `mem_limit` و `nano_cpus` واقعاً محدود می‌شود و شبکه داکر جدا دارد.

## امنیت — آنچه MVP هست و آنچه نیست

✅ هست:
- رمزها با scrypt هش می‌شوند؛ نشست‌ها کوکی امضاشده HttpOnly+SameSite
- فرم‌های POST با توکن CSRF محافظت می‌شوند
- ثبت‌نام گیتا بسته است؛ همه چیز از API پرستو
- کانتینرهای سایت محدود به منابع، بدون privileged، شبکه ایزوله
- وب‌هوک‌ها با امضای HMAC اعتبارسنجی می‌شوند

⚠️ برای تولیدی‌شدن جدی، به‌عنوان گام بعد لازم است:
- رمزنگاری توکن‌های گیت در دیتابیس (الان در db ذخیره شده‌اند)
- Rate limit روی ورود/ثبت‌نام
- بیلد در محیط ایزوله‌تر (rootless buildkit / gVisor)
- بکاپ خودکار زمان‌بندی‌شده و مانیتورینگ
