# پرستو (Parastoo)

> مخاطب: انسان — مالک/نصاب/توسعه‌دهندهٔ تازه‌وارد · عامل‌ها: از INDEX §۲ و ROLES وارد شوید

[![CI](https://github.com/SelfEvolvingNetwork/parastoo/actions/workflows/ci.yml/badge.svg)](https://github.com/SelfEvolvingNetwork/parastoo/actions/workflows/ci.yml)

پلتفرم خودمیزبانِ «ساخت، انتشار و فروش» وب‌اپلیکیشن‌ها — روی یک سرور اوبونتو، با یک دستور.

پرستو یک mini-PaaS است: کاربر ثبت‌نام می‌کند، پروژه می‌سازد، کدش را با توکن روی مخزن گیت داخلی push می‌کند، پرستو خودکار ایمیج می‌سازد، آن را روی زیردامنه منتشر می‌کند، منابع (CPU/RAM) را محدود و هزینه را ساعتی از کیف پول کسر می‌کند — و ایمیج‌ها را می‌توان در مارکت‌پلیس به دیگران فروخت.

## مستندات — از کجا شروع کنم؟

**نقشهٔ جامع خانوادهٔ پرستو و فهرست «موضوع → سند مرجع»:** [`docs/INDEX.fa.md`](docs/INDEX.fa.md) — تنها درگاه ورود به مستندات (خانوادهٔ ۴مخزنی، ترتیب خواندن شروع سرد، قرارداد نگهداری). تازه‌وارد: اول INDEX، بعد همین README، بعد `docs/AI_AGENT_LOOP.fa.md`، بعد WORKLOG §۵ کامل.

## معماری در یک نگاه

| نقش | ابزار |
|---|---|
| کنترل‌پلین (پنل، API، ورکرها) | Python / FastAPI — کد خود پرستو (`core/`) |
| گیت داخلی + رجیستری ایمیج OCI | Gitea |
| بیلد و اجرای سایت‌ها | Docker (از طریق Docker SDK) |
| پروکسی، دامنه، HTTPS خودکار | Traefik |
| نیم‌سرور اختصاصی (DNS) | PowerDNS Authoritative |
| دیتابیس | PostgreSQL |

هیچ Kubernetes، GitLab یا نرم‌افزار سنگینی در کار نیست؛ پرستو فقط «چسب نازک» بین ابزارهای بالغ است و تمام منطق کسب‌وکار (کاربر، پروژه، مارکت‌پلیس، کیف پول) در `core/` قرار می‌گیرد.

پروژه‌ها **سرویس‌محورند**: هر مخزن می‌تواند مانیفست `parastoo.yml` داشته باشد (تا ۸ سرویس: وب، دیتابیس، کش و…)؛ هر پروژه شبکهٔ خصوصی خودش را دارد و فقط سرویس عمومی‌اش از `https://<slug>.apps.<دامنه>` سرو می‌شود. نقشهٔ کامل معماری و قرارداد ارتباط سرویس‌ها: [docs/DEVELOPMENT.fa.md](docs/DEVELOPMENT.fa.md)

## نصب — یک دستور، مستقیم از گیت‌هاب

مخزن رسمی: `github.com/SelfEvolvingNetwork/parastoo`
روی یک سرور تازه اوبونتو ۲۲/۲۴ (حداقل ۲GB رم، توصیه‌شده ۴GB)، از طریق SSH همین یک خط:

```bash
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/parastoo/main/bootstrap.sh | sudo bash
```

`bootstrap.sh` بسته را از گیت‌هاب می‌گیرد (ترتیب تلاش برای `main`: تاربال مخزن ← ریلیز zip ← git clone) و در `/opt/parastoo` می‌ریزد و `install.sh` را اجرا می‌کند — داکر، عبور از تحریم، توکن نصب و کل استک، همه خودکار.

قواعد نصب (هر کدام یک خط):

- **نسخهٔ پایدار به‌جای main:** `... | sudo env PARASTOO_REF=vX.Y.Z bash`
- **دامنهٔ آماده:** `sudo env PARASTOO_BASE_DOMAIN=example.com bash install.sh` — سه رکورد A به IP سرور: `panel.` و `git.` و `*.apps.`
- **متغیرها همیشه با `sudo env`** بدهید؛ فرم `sudo VAR=x bash` روی پیکربندی پیش‌فرض sudo بی‌صدا متغیر را حذف می‌کند.
- **IP سرور:** نصب‌کننده IP را خودکار تشخیص می‌دهد؛ روی سرورهای پشت NAT اگر پنل باز نشد، با `sudo env PARASTOO_PUBLIC_IP=<IP واقعی سرور>` دوباره اجرا کنید. مقدار صریح بر دامنهٔ کهنهٔ `.env` غلبه می‌کند و `.env`/لیبل روتر/URL چاپ‌شده بازنویسی می‌شوند.
- **اگر در ایران گیت‌هاب کند بود:** پیشوند `https://gh-proxy.com/` را به همان URL بدهید (تنها روشِ جایگزینِ همان یک مسیر).
- **زبان خروجی نصب:** ترمینال هنگام نصب کاملاً انگلیسی است — متن فارسی/RTL در SSH به‌هم می‌ریزد. پنل وب و مستندات فارسی‌اند.
- **CA گواهی جایگزین:** `PARASTOO_ACME_CA=zerossl` + کلیدهای EAB (از داشبورد زروسsl بگیرید؛ API آن از ایران 403 می‌دهد). زروسsl برای دامنه‌های `.ir` گواهی صادر نمی‌کند — دامنهٔ ایرانی همیشه پیش‌فرض لت‌انکریپت.
- **گواهی وایلدکارد:** وقتی زون دامنه روی نیم‌سرور خود پرستو باشد، فقط سه گواهی با چالش DNS-01 صادر می‌شود — `*.<دامنه>` + `<دامنه>` + `*.apps.<دامنه>` — و بی‌نهایت هاست/سایت را می‌پوشاند؛ صدومین سایت هم سفارش ACME تازه نمی‌خواهد. نصب روی `nip.io` یا زون بیرونی: HTTP-01 به‌ازای هر هاست.
- **قانون گواهی ماندگار:** گواهی‌ها در `/var/lib/parastoo/tls` آینه می‌شوند و **هرگز پاک نمی‌شوند** — نصب مجدد، ریست کارخانه و تست‌ها پیش از هر درخواست ACME اول از همان بازیابی می‌کنند؛ فقط گواهی واقعاً غایب از CA خواسته می‌شود و سقف نرخ لت‌انکریپت با نصب‌های مکرر گاز نمی‌گیرد. وضعیت: `sudo bash scripts/tls-store.sh status`
- **اجرای مجدد = آپدیت امن:** همان دستور را دوباره بزنید؛ کد به‌روز می‌شود ولی `.env`، پیکربندی ترافیک، بستهٔ آفلاین، پشتیبان‌ها و داده‌ها (ولیوم‌های داکر) دست‌نخورده می‌مانند.

> نصب پرستو فقط از همین یک مسیر است (گیت‌هاب ← bootstrap.sh ← install.sh). نسخهٔ zip ریلیزها فقط منبعِ دانلودِ خودِ bootstrap.sh است، نه روشی جدا برای نصب دستی.

### install.sh چه می‌کند (هیچ سوالی نمی‌پرسد)
1. داکر را نصب می‌کند (اگر نباشد)
2. دامنه موقت از IP سرور می‌سازد (`*.nip.io`)
3. همه رمزها را تصادفی می‌سازد و در `.env` ذخیره می‌کند (chmod 600)
4. یک **توکن نصب یک‌بارمصرف** تولید و در خروجی چاپ می‌کند
5. کل استک را با `docker compose` بالا می‌آورد و CLI `parastoo` را نصب می‌کند

در پایان، آدرس پنل + توکن نصب چاپ می‌شود. بقیه‌اش در مرورگر:

### ویزارد راه‌اندازی (۳ گام در پنل وب)
1. **توکن نصب** — همان توکنی که ترمینال چاپ کرده؛ تضمین می‌کند فقط کسی که به ترمینال سرور دسترسی دارد ویزارد را کامل کند.
2. **حساب مدیر** — بعد از این گام، ویزارد برای همیشه بسته می‌شود.
3. **دامنه و HTTPS** — دامنه واقعی، ایمیل Let's Encrypt و بررسی زندهٔ رکوردهای DNS؛ اعمال دامنه بدون قطعی و بدون ری‌استارت هسته. این صفحه همیشه از منوی «دامنه‌ها» در دسترس ادمین است.

## سیکل کاربر (خلاصهٔ استفاده)

1. **ثبت‌نام** در پنل ← حساب گیت + توکن دسترسی خودکار ساخته می‌شود
2. **پروژه جدید**: نام + شناسه + توضیح — مخزن با بذر جهانیِ آمادهٔ اجرا ساخته می‌شود (از v0.5.2 دیگر مدل/فناوری پرسیده نمی‌شود)؛ هرگز از مخزن خالی شروع نمی‌کنید.
3. **کلون و push** مثل گیت‌هاب:
   ```bash
   git clone https://<user>:<token>@git.example.com/<user>/<project>.git
   cd <project>
   # ... تغییرات ...
   git add -A && git commit -m "تغییرات" && git push
   ```
4. با هر push ← بیلد خودکار ← ایمیج جدید در رجیستری ← **به‌روزرسانی خودکار همه سایت‌های وابسته**
5. **انتشار سایت**: زیردامنه + پلن منابع (هزینه ساعتی از کیف پول)
6. **مارکت‌پلیس**: پروژه را عمومی کنید (رایگان یا قیمتی)؛ دیگران با یک فرم آن را روی حساب خود فعال می‌کنند؛ فروشنده بعد از کمیسیون، درآمد را در کیف پول می‌بیند.
7. **فروش مستقیم (v0.5.19)**: صفحهٔ عمومی `/pricing` با قیمت‌های بازارمحور، فرم سفارش عمومی `/order` (سرنخ فروش در «پنل کسب‌وکار» ادمین `/admin/business`) و صفحهٔ وضعیت زندهٔ `/status` (تپش‌نگار پایداری، هر ۱۰ دقیقه).

> نکته: اپ‌های Node/Python باید روی پورت 3000 گوش دهند (`PORT=3000` به کانتینر تزریق می‌شود)؛ با مانیفست `parastoo.yml` هر پورتی انتخاب می‌شود. اگر در ریشه مخزن `Dockerfile` بگذارید، پرستو از آن استفاده می‌کند. اگر مخزن با استک ناهم‌خوان باشد، بیلد با پیام فارسیِ قابل‌اقدام متوقف می‌شود، نه خطای مبهم داکر.

## ارتباط سرویس‌ها (قرارداد فشرده)

- **درون-پروژه:** نام سرویسِ مانیفست + پورت مانیفست مقصد (`db:5432`) روی شبکهٔ خصوصی پروژه؛ سرویس‌های غیرعمومی از بیرون و از همسایه‌ها به‌ساختاری نامرئی‌اند.
- **بین-پروژه و از وب جهانی:** فقط درِ واحد `https://<slug>.apps.<دامنه>` — فراخوانندهٔ همسایه و وب دقیقاً یک رفتار می‌بینند؛ احراز هویت کار خودِ اپ است (دسترس‌پذیری ≠ اعتماد).
- نام‌های پلتفرم در `/etc/hosts` کانتینرهای پروژه پین می‌شوند (DNS خوداتکا) تا فراخوانی شرق-غرب به DNS بالادست وابسته نماند.
- قرارداد کامل: [docs/DEVELOPMENT.fa.md](docs/DEVELOPMENT.fa.md) — بخش «قرارداد ارتباط سرویس‌ها»

## پل عامل هوش مصنوعی (پروژه‌محور)

از v0.5.28 راه پیشنهادی اتصال عامل، **جفت‌سازی بدون توکن با رمز سرورساخته** است: کاربر در صفحهٔ پروژه «متن دعوت» بی‌رمز را کپی می‌کند (لورفتنش بی‌خطر است؛ مخصوص همان پروژه)، عامل آدرس دعوت را GET می‌کند و **سرور خودش رمز ۵ رقمی یک‌بارمصرف را می‌سازد و به عامل می‌دهد تا فقط برای کاربر چاپش کند** — عامل هیچ محاسبه‌ای انجام نمی‌دهد؛ کاربر همان رمز را در فرم «تأیید عامل» تأیید می‌کند و عامل توکن `pst_…` را مستقیم از سرور می‌گیرد — هیچ رازی از چت عبور نمی‌کند. مسیر قدیمی (ساخت دستی توکن و گذاشتنش در چت) هنوز هست اما توصیه نمی‌شود.

در مسیر قدیمی کاربر در صفحهٔ پروژه یک **توکن عامل** (`pst_…`) می‌سازد و به عامل کدنویس خودش (Claude Code/Cursor/…) می‌دهد؛ عامل با همان توکن پوش می‌کند (بدون توکن گیتِ حساب کاربر)، بیلد و لاگ را می‌بیند، داخل کانتینرها تست/عیب‌یابی می‌کند و سرویس را ری‌استارت می‌کند — **فقط روی همان پروژه** (توکن فقط هش دارد، کشف کانتینر با لیبل پروژه، سقف نرخ/خروجی/زمان، audit کامل، ابطال فوری).

ابزار: `curl -fsSL https://panel.<دامنه>/static/pst.py -o pst.py` — قرارداد کامل: [docs/AGENT_BRIDGE.fa.md](docs/AGENT_BRIDGE.fa.md)

## فقط دو دستور رسمی — نصب/آپدیت و ریست فکتوری

```bash
# دستور ۱ — نصب و به‌روزرسانی (اجرای مجدد = آپدیت امن؛ داده‌ها دست‌نخورده):
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/parastoo/main/bootstrap.sh | sudo bash

# دستور ۲ — ریست فکتوری (پاک‌سازی کامل داده‌ها + بازسازی استک با سلامت‌سنجی):
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/parastoo/main/scripts/factory-reset.sh | sudo bash
```

(در ایران اگر گیت‌هاب کند بود، پیشوند `https://gh-proxy.com/` را به همان URL اضافه کنید.)

- **دستور ۱** اگر پرستو نصب نباشد نصب می‌کند و اگر باشد کد را به‌روز می‌کند (`.env`، پیکربندی ترافیک، بکاپ‌ها و داده‌ها حفظ می‌شوند).
- **دستور ۲** به‌ترتیب: بکاپ best-effort دیتابیس ← حذف کانتینرهای پروژه (داخل و خارج استک) ← حذف ولوم‌های `parastoo_*` با تأیید واقعی ← پاکسازی شبکه‌ها و ایمیج‌های پروژه‌ها ← `docker compose up -d --build` ← انتظار برای پاسخ سلامت هسته؛ فقط با هستهٔ سالم «بازگشت به تنظیمات کارخانه» اعلام می‌شود. کد، `.env` و پشتیبان‌ها می‌مانند؛ گواهی‌ها از فروشگاه ماندگار بازگردانی می‌شوند.
- برای خودکارسازی ریست: `--yes` یا `PARASTOO_RESET_CONFIRM=yes` (تأیید تعاملی از `/dev/tty` خوانده می‌شود، هرگز از stdin — پس `curl | bash` امن است).

## ابزارهای روی سرور

```bash
parastoo status     # وضعیت سرویس‌ها
parastoo logs core  # لاگ هسته (یا gitea/traefik/postgres/dns)
parastoo restart    # ری‌استارت استک
parastoo update     # آپدیت از گیت‌هاب (کد جدید + بازسازی هسته)
parastoo autoupdate # کنترل آپدیت خودکار: status | on | off | run
parastoo backup     # پشتیبان دیتابیس + مخزن‌ها + گواهی‌ها در backups/
parastoo reset      # همان ریست فکتوری (دستور ۲) از داخل سرور
parastoo doctor     # گزارش کامل عیب‌یابی (رمزها مخفی)
sudo bash uninstall.sh   # حذف کامل
```

## آپدیت از گیت‌هاب (v0.5.13 — تایمر پیش‌فرض مسلح)

استقرار خودکار است (فرمان مالک 2026-11-09: «بروزرسانی باید اتوماتیک باشد و نباید پرسیده شود»؛ نصب/حذف/نصب مجدد همچنان فقط صریح است). موتور مشترکِ آپدیت `scripts/auto-update.sh` است و مسیرها:

```bash
parastoo update                   # آپدیت فوری از گیت‌هاب (همان مسیر lifecycle پل)
# یا از پرستو موبایل: صفحهٔ «مدیریت پرستو» → به‌روزرسانی (POST /api/admin/parastoo/update)
parastoo autoupdate status        # پیکربندی + تاریخچهٔ آخرین آپدها
parastoo autoupdate on            # مسلح‌کردن دوبارهٔ تایمر (پیش‌فرض مسلح از v0.5.13)
parastoo autoupdate off           # خاموش کردن
```

هر استقرار (خودکار یا صریح) جایگزین امنِ فقط-کد + بکاپ خودکار + تاریخچهٔ `logs/updates.jsonl` است.

**بررسی نسخه بدون SSH:**

```bash
curl -s https://panel.example.com/api/version
# {"ok":true,"app":"parastoo","version":"...","commit":"abc123...","deployed_at":"..."}
```

تاریخچهٔ هر استقرار در `/opt/parastoo/logs/updates.jsonl` ثبت می‌شود.

## نیم‌سرور اختصاصی — DNS

پرستو می‌تواند «مرجع رسمی DNS» باشد: هر دامنه‌ای که نیم‌سرورهایش را روی سرور شما بگذارند (مثل دامنهٔ خودتان یا دامنهٔ مشتری‌ها)، از پنل ادمین مدیریت می‌شود:

- **منوی «DNS» در پنل (ادمین):** ساخت زون با یک کلیک (`customer` یا `base`)، افزودن/ویرایش/حذف رکورد (A/AAAA/CNAME/MX/TXT/NS/SRV/CAA)، حذف زون.
- **سرویس `dns` در compose:** PowerDNS Authoritative با SQLite در volume؛ پورت ۵۳ سرور جواب می‌دهد؛ API آن فقط داخل شبکهٔ داکر است.
- **API:** `GET/POST /api/dns/zones|records` — با نشست ادمین یا هدر `X-Dev-Token`.
- راهنمای کامل فارسی (ایرنیک، گلو-رکورد، پذیرش دامنهٔ مشتری، ns2 دوم، عیب‌یابی): **`docs/DOMAIN_DNS_GUIDE.fa.md`**

## کنسول توسعه (همیشه روشن)

معماری پرستو **واحد** است — تجاریِ همواره در حال توسعه مستمر (فرمان مالک ۲۰۲۶-۱۱-۱۲: حذف مفهوم دو-حالتی توسعه‌دهنده/تجاری). ابزارهای عملیاتی همیشه جزء محصول‌اند و ملاک دسترسی فقط احراز هویت است. توکن اختیاری (برای دسترسی curl/عامل بدون لاگین) در `.env`:

```
PARASTOO_DEV_TOKEN=یک-رشته-تصادفی   # اختیاری؛ هدر X-Dev-Token
```

منوی «توسعه» (ادمین) و صفحه `/dev` همیشه در دسترس‌اند: گزارش زنده (نسخه/کامیت مستقر، سلامت، تاریخچهٔ آپدیت، بیلدهای ناموفق، لاگ زندهٔ هسته) و APIهای `GET /api/dev/report|logs|updates|netcheck` و `POST /api/dev/sql`. دسترسی: ادمینِ واردشده یا هدر `X-Dev-Token`. بدون احراز معتبر پاسخ **401** است (شفاف — وجود این لایه پنهان نیست).

**بازگشت به تنظیمات کارخانه:** با دستور ۲ بالا (`curl ... scripts/factory-reset.sh | sudo bash` یا همان `parastoo reset`). برای حذف کامل به‌همراه کد: `sudo bash uninstall.sh` (به سوال ولوم‌ها «y» بدهید) و سپس با دستور ۱ دوباره نصب کنید.

## شارژ کیف پول (MVP)

در این نسخه، شارژ کیف پول از **پنل مدیریت → کاربران** به‌صورت دستی انجام می‌شود (درگاه آزمایشی mock در `routes/payment.py` فعال است؛ درگاه واقعی مسیر رشد). اگر موجودی کاربر به سقف بدهی برسد، پروژه‌هایش خودکار متوقف می‌شوند و بعد از شارژ می‌تواند دوباره روشنشان کند.

## سربار منابع و قیمت‌گذاری

پلن‌ها در `core/app/config.py` (`TIERS`) تعریف شده‌اند: نانو (0.25CPU/256MB)، کوچک (0.5/512)، متوسط (1/1024) — با قیمت ساعتی پیش‌فرض که از `.env` هم قابل تغییر است (`PARASTOO_COMMISSION`، `PARASTOO_DEBT_LIMIT`). هر سرویس با `mem_limit` و `nano_cpus` واقعاً محدود می‌شود و شبکهٔ داکر جدا دارد؛ صورتحساب = جمع سرویس‌های running پروژه.

## امنیت — آنچه MVP هست و آنچه نیست

✅ هست:
- رمزها با scrypt هش می‌شوند؛ نشست‌ها کوکی امضاشده HttpOnly+SameSite
- فرم‌های POST با توکن CSRF محافظت می‌شوند
- ثبت‌نام گیتا بسته است؛ همه چیز از API پرستو
- کانتینرهای سایت محدود به منابع، بدون privileged، شبکهٔ خصوصیِ ایزوله به‌ازای هر پروژه
- وب‌هوک‌ها با امضای HMAC اعتبارسنجی می‌شوند
- توکن عامل فقط هش دارد، دانهٔ دسترسی‌اش یک پروژه است و audit کامل دارد

⚠️ برای تولیدی‌شدن جدی، به‌عنوان گام بعد لازم است:
- رمزنگاری توکن‌های گیت در دیتابیس (الان در db ذخیره شده‌اند)
- Rate limit روی ورود/ثبت‌نام
- بیلد در محیط ایزوله‌تر (rootless buildkit / gVisor)
- بکاپ خودکار زمان‌بندی‌شده و مانیتورینگ
